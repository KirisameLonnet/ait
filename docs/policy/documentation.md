# 文档维护规范

文档描述当前源码和可执行流程。每份文档应有明确用途和归属，路径、命令和链接随代码更新。

## 分类

| 目录                   | 内容                                       |
| ---------------------- | ------------------------------------------ |
| `architecture/`        | 当前组件职责、依赖与数据所有权             |
| `decisions/daemon/`    | daemon、协议、运行资源和能力分发决策       |
| `decisions/workspace/` | Project/Workspace、文件、Git 和 Forge 决策 |
| `decisions/providers/` | Provider、Agent、会话和时间线决策          |
| `decisions/clients/`   | 桌面、移动端、Web、SDK、连接和发布决策     |
| `decisions/branding/`  | 品牌与视觉决策                             |
| `operations/`          | 用户与维护者可执行的配置、构建和发布流程   |
| `policy/`              | 工程约束与贡献规范                         |
| `plans/`               | 仍有未完成工作的能力清单                   |
| `reports/`             | 按主题归类的实施验证与发布记录             |
| `assets/`              | 当前决策仍引用的设计资源                   |

## 更新与清理

1. 影响长期边界的修改增加 ADR，并更新 `docs/README.md` 与对应分类索引。
2. ADR 使用唯一递增编号、标题、状态、日期、背景、决策和后果；修订旧决策时明确写出关系。
3. 运维文档中的命令应能对应当前脚本；能力数量等易变化信息应引用运行时查询或权威清单。
4. 验证报告注明源码提交、平台、命令、范围和限制，测试结果与覆盖率分开记录。
   Rust 报告遵循 [Rust style guide](rust.md) 的 Test coverage 要求；历史覆盖率不代表当前覆盖率。
5. 删除已移除实现的说明、过期计划和无关实验资料；从 Git 查阅历史，不在当前索引重复维护。
6. 保留仍可用于验证当前行为的报告、第三方来源、许可证和当前资产。
7. 移动或删除文档时同步修复引用，并运行 `npm run check:docs`；该检查只访问本地链接。

入口 README 简述用途并链接详细文档，避免重复复制架构与操作步骤。
